# /refactor — Пошаговый рефакторинг

Строго следуй этим четырём фазам. Не переходи к следующей без сигнала пользователя.

---

## Фаза 1 — Анализ (выполни сам, без остановок)

1. Прочитай все указанные файлы
2. Составь нумерованный список замечаний на русском
3. Для каждого замечания укажи: файл + строка, проблема, предлагаемое решение
4. **СТОП** — выведи список и жди ответа пользователя

Формат:
```
## Замечания по рефакторингу

1. `tests/tree/test_foo.py:42` — [краткое описание проблемы]
   Решение: [что сделать]

2. `tests/pages/bar.py:17` — ...
   Решение: ...
```

---

## Фаза 2 — Подтверждение (ждёшь пользователя)

Пользователь либо:
- Говорит «всё» / «делай» → реализуй все пункты
- Называет номера → реализуй только их
- Исключает номера → пропусти их

**Не начинай реализацию до явного ответа.**

---

## Фаза 3 — Реализация (по одному пункту)

Для каждого выбранного пункта:
1. Внеси изменения
2. Запусти: `ruff check <файл>` и `python scripts/check_drift.py`
3. Коротко сообщи что сделано
4. Переходи к следующему

Если ошибка не исправляется за 1 попытку — сообщи и перейди к следующему.

---

## Фаза 4 — Коммит

После всех изменений:
1. Выведи сводку: что сделано, что пропущено, что заблокировано
2. Предложи текст коммита на русском
3. Жди подтверждения перед `git commit`

---

## Важно

- Все сообщения — на русском
- Никогда не пропускать Фазу 1
- После анализа — сразу реализация (без повторного планирования)
- Проверять правила CLAUDE.md (30 правил) при рефакторинге
